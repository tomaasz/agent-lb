# Audyt AgentLB — 2026-10-22

Audyt i poprawki na bazie `9841a14`, gałąź `ai/deep-audit-2026-10-22`.
Najpoważniejszy wynik: klucz delegowanej stacji pozwalał uzyskać sesję administratora
oraz odczytać pozostałe poświadczenia puli. Poprawka usuwa tę eskalację.

## Zakres i metoda

Przegląd kontroli dostępu HTTP, sesji panelu, resetowania hasła, wejść i mutacji
administracyjnych, zarządzania zużyciem, panelu, przekazywania ruchu, limitów
pamięci, logowania i deklaracji zależności. Analiza statyczna, testy HTTP na
lokalnym listenerze z atrapami kont, testy logiki i skryptu panelu w VM,
niezależny read-only review, lint i testy regresji. Skan 192 śledzonych plików
pod kątem wybranych formatów kluczy API, JWT i prywatnych kluczy nie znalazł
pasujących wartości. To nie jest skan historii Git ani konfiguracji produkcyjnej.
Nie korzystano z prawdziwych kont, nie wysyłano e-maili i nie wdrażano zmian.

W tabelach **lokalizacja źródłowa** odnosi się do wersji `9841a14` przed
poprawkami. Podano fragmenty kodu identyfikujące problem; nie zawierają sekretów.
Wszystkie poniższe findingi zostały poprawione w tej gałęzi.

## Zmiany zachowania i granice

- Dawne sesje panelu wymagają ponownego logowania. Delegowane klucze pozostają
  kluczami API do wnioskowania i nie dają wejścia do administracji.
- Własna domena panelu wymaga `proxy.webAuth.publicUrl` dla poprawnych linków
  resetu. Reset pocztowy wymaga jawnego `proxy.webAuth.email`; nie ma ukrytego
  prywatnego adresu awaryjnego. Transport SMTP pozostał dotychczasowy i nie był
  testowany na żywym serwerze.
- Instalacja poza Dockerem wymaga `python3` z modułem `bcrypt` dla haseł;
  brak helpera odmawia logowania i zapisuje ogólny błąd. Główny klucz działa bez niego.
- Limity auth są lokalne dla procesu. Klienci za jednym reverse proxy dzielą
  budżet jego socketu. Restart zeruje te liczniki; nie jest to rozproszony limiter.
- Główny klucz wpisany ręcznie nadal używa dotychczasowego localStorage; poprawka
  usuwa trwały cache wszystkich kluczy stacji. Zmiana tego modelu wymaga osobnej
  migracji sposobu uwierzytelniania panelu.
- Testy skryptu panelu używają VM i atrap DOM; nie zastępują pełnego testu
  w prawdziwej przeglądarce. Nie sprawdzano uprawnień ani sekretów na produkcji.
- Zastane zmiany instalatora Hermesa i `.claude/settings.json` nie należą do poprawki.
